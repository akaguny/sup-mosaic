# Порядок работы агента

Рабочий процесс и правила стиля описаны в скилле **sup-keychain-stencils**; здесь — как он ложится на файлы проекта.

## Начало сессии

1. Загрузите скилл **sup-keychain-stencils**.
2. Прочитайте `AGENTS.md` и [статус](status.md): что сделано, что следующее.
3. Скачайте проект: `Artifact list` со `scope: "files"`, затем `Artifact read` с `paths` — все файлы ложатся в папку артефакта в scratchpad с той же структурой. Работайте в этой копии, не пишите проект заново.
4. Фото — из PDF-выгрузки пользователя: `python3 -I tools/photos.py images выгрузка.pdf папка` (пишет `index.json`: № позиции → файл). Папку с фото держите отдельно от скриптов.

## От фото к брелоку

| Шаг | Инструмент |
|---|---|
| Сгруппировать карточки по рисунку: размеры одной модели и близнецы — один рисунок, разные цвета — перекраска | глазами, по листу фото |
| Обрезать доску носом вверх | `tools/photos.py crop фото выход [rot] [kit]` |
| Черновик раскладки зон (необязательно) | `tools/raster.py фото тип N W цвета… --prio …` |
| Цвета ролей | `tools/photo_colors.py` (подсказка и лист образцов) → `tools/raster.py nearest r,g,b` |
| Нарисовать сетку кодом | `tools/artkit.py`: `base`, `put`, `fill`, `where`, `V`, профили `AR9`, `TR9`, `RC9`, `AR11`, `RC5` |
| Записать в данные | `add_keychain(...)` или скрипт пачки по образцу `tools/designs_batch2.py` (новые сетки, перекраски, ссылки `keychain`) |
| Лист сверки | `tools/review.py лист.png ключ[@модель]=фото[:rot[:kit]] …` → пользователю через SendUserFile |
| Проверка | `python3 -m http.server 8765 -d <папка> &` и `NODE_PATH=$(npm root -g) node tools/check.js http://localhost:8765/` — `errors: []` |

`check.js` проверяет, что каталог загрузился, у каждой полноразмерной доски есть брелок, работают фильтры «Брелоки» и «По фото» и кнопка «Брелок».

Скрипты пачек (`designs_batch1.py`, `designs_batch2.py`) — история: повторный запуск перезапишет ручные правки этих сеток в `art.json`.

## Публикация

- Тот же URL: `file_path` — `index.html` проекта, `root` — папка проекта, в `files` — только изменённые файлы (остальные сохраняются).
- `.py` — `{"from": …, "contentType": "text/plain"}`, `.md` и `.html` — как есть.
- Каждый раз обновляйте документацию: статус позиций, новые цвета, решения, открытые вопросы, запись в `CHANGELOG.md`.
- Возможности артефакта не передавайте.
- Публикуйте после согласия пользователя, если вариантов было несколько.

## Пачки

Работайте пачками по 8–10 рисунков, после каждой — лист сверки. Если пользователь просит «дополнить» без указания досок — берите следующий незакрытый блок из [статуса](status.md) и в первой строке ответа скажите, какой взяли.
